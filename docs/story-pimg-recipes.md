# Explicit save-gated PIMG recipes

A story document may declare pimgRecipes. Each variant must be in its gallery. A recipe binds one source XP3/entry raw SHA256, decoded SHA256 and optional exact existing filter title; one mapping XP3/entry SHA256 and exact image/selection row; and an explicit ordered list of layer id/name pairs. It contains no images, paths outside the game, player save values or executable commands. Order is reviewed data: no general reversal or other seton interpretation is inferred.

Only two Senren recipes are currently backed by the saved static receipt: EV701AA with Aa/id3, and EV701AB with Aa/id3 then Ab/id4. The version is bound by the adjacent story EXE/script anchors. All other PIMG combinations remain unsupported until an explicit verified recipe is supplied. Generic support for arbitrary seton behavior is not claimed.

The existing story identity worker includes recipe data in its proof key and prepares the CG index. It validates raw/decoded source hashes, complete mapping bytes and the unique exact mapping row, and matches actual PIMG metadata ids and names. The result is transferred through the existing CG snapshot protocol. The bridge only consumes this prepared index/cache; an unprepared main-thread request cannot start PIMG composition. Changed image or mapping source stats revoke the primed index and request a new existing analysis job. Per-variant cache identities include the recipe and source/mapping canonical stat signatures.

The existing card-wall warm child receives the finite pure-data recipes with its job, independently verifies them, checks current explicit cg_ save marks, then runs the PIMG reader/compositor/PNG writer there. Its nested TLG Workers still await actual exit. No second resident scheduler or model is introduced. PIMG input is limited to 32 MiB, canvas to 4 megapixels, selected decoded layer pixels to 16 megapixels, output PNG to 24 MiB and available memory to at least 1 GiB before composition. New recipe segment reads are finite, validate sums/ranges and use bounded zlib output. The inherited XP3 index reader is reused in the isolated context; these bounds are not a total RSS or general hostile-archive safety guarantee.

Neutral integration tests use a controlled archive index/thumbnail transport and real production mapping, warmRun, compositor, TLG Workers, PNG encoding and private snapshot transfer in an owned Node child with a five-second deadline and 128 MiB V8 heap. They prove the finite path and source/save negative controls, not game-screen acceptance. No real game archive was extracted for this integration while the three-drive resource gate was closed.

Current static classification coverage: Josou has 240 declared variants with an adult whole-game fallback from VNDB v6589 releases; no local release id or individual H/general mapping is asserted. Senren has 975 declared variants with unknown whole-game fallback because the current script edition has not been bound to the distinct non-ero/adult releases. Verified individual H-scene counts remain unknown for both. Five real-picture checks per title and actual bridge delivery remain outstanding.
