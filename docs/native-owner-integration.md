# Private native source integration

Base: `ba27451f2a0727fee5f17e684480d13bd1c656f8`

This closes the existing DR1 PC source candidate's shared JavaScript path and the private launch environment for the measured Musica and IGA candidates. Native source and build scripts are unchanged by this increment

## DR1 PC

The actual HookNative stream receiver calls the existing DR1 adapter before the ordinary source path. Source, deferred delivery and final emission all require its private Symbol receipt, the real opaque owner token, current process ID/birth and current bridge serial. A raw profile flag, JSON token copy, public origin string or an old callback cannot enable the native control or deliver text

`engineDrawProfile()` filters this input flag at the actual EngineDraw boundary unless the current opaque permission is valid. The control is flushed before bridge startup only for that permission. The accepted owner draw key is `spikechunsoftInput`; its existing engine-specific and `diagnostic-input` capability checks remain unchanged

This source proposal is ADV only. A private DR1 source refuses NVL rather than passing through a page queue that cannot carry its authority. It supplies no native geometry, speaker/choice classification, ruby, hide or embedding permission

Revocation and direct grant removal clear only a currently delivered DR1 source. A later unrelated source is preserved. Wanted-off, a pending/failed stop, disposal, mismatched birth and changed serial reject late callbacks. The existing asynchronous stop, all-settled cleanup and owned-helper wait remain in place. A clear notification failure is logged and cannot interrupt permission removal or helper shutdown; a successful clear is not a native drain acknowledgement

## Private launcher environment

The normal isolated launcher strips inherited MeguLit and injection flags, then derives additional native environment only from its actual validated local owner catalog

- Musica requires exactly one catalog entry matching both measured EXE and `scr.dat` hashes/sizes. The launcher reads at most the fixed pair sizes (1126400 and 6134556 bytes), refuses reparse paths and changed file/handle stamps, and calls the existing real PE/pair inspector. Only then does it supply `MEGULIT_MUSICA_BASIC=<exact hash>` and `MEGULIT_MUSICA_EXE=<canonical exact path>`
- IGA recognizes the existing catalog engine name `innocentgrey` as well as `iga`, and supplies only `MEGULIT_IGA_TEXT=1`. The existing `MEGULIT_OWNER_TESTS=1` and `MEGULIT_SIDE_BY_SIDE=1` are also required. Native code independently verifies the EXE and eight plugin/resource files; this flag does not replace those nine full hashes
- `MEGULIT_UNIFIED_ADAPTERS=1`, relay-off and isolated temporary folders remain unchanged

Musica/IGA remain ordinary read-only Luna source streams using the existing bridge enable/disable path. They do not gain the DR1 Symbol protocol or any new role/hide/embed claims. The private environment is not a dynamic native grant acknowledgement

Root alone imports private metadata and deploys. The local proposal receipt is `H:/MeguLit-Work/night-1423/native-owner-integration/import-metadata.json`; it contains no save/config fingerprint. The existing Musica installation passed the real bounded pair inspector without being launched, recorded in `musica-pair.json`. No game files were changed

## Verification scope

`validation/native-owner-integration.test.cjs` uses real OwnerTests and HookNative classes with neutral EXE/resource identities, pipe-fed controlled HookBridge messages and an explicitly fake spawned helper. The transport test stubs dependency acquisition so it cannot download a runtime. It does not execute the fake EXE/DLL files or claim the neutral files satisfy native game pins

It covers ordinary ADV delivery, actual control filtering, default-off, JSON token clones, reserved/public origin misuse, history, late source and final delivery, revoke, direct removal, same PID with a different birth, stop(false) waiting for the owned helper's controlled exit, notification failure, bridge-error generations and NVL refusal. Launcher tests use a controlled spawn callback and never start MeguLit or a game

Related stop, native-ruby, Artemis, Unity, RGSS, library-only and engine opt-in suites are run together with the native adapter tests. Final gameplay, ten live lines, actual translation/lookup quality and native installation remain owner acceptance items; no test result here is a live or release acceptance
